# five_free 经验公开与 Pages 发布规范 V1.2

## 第一原则

**网站为主、经验为辅。** 原有 `index.html`、`assets/`、27 章内容、210 词卡、SVG 视觉、PC/H5 路由与本机学习记录均不得因仓库治理而损坏。此仓库是 Public：任何提交、分支、PR 和 Actions 日志均可能被公众读取，不能先上传未授权资料再删。

## 第一道门禁：进入公开仓库之前

经验必须在有权使用的私有环境完成：
- 权属/保密/知识产权及雇主、合作主体许可核验，明确**有权公开**；
- 脱敏复核：不包含可识别的内部产品、专有代码/架构、商业计划、合同、客户及医疗个人信息、病历/处方/影像、真实截图、域名、私有仓库/版本组合、API 密钥、内网地址与原始日志；
- 避免组合线索反向识别，以虚构/合成样例替代真实资料；
- 人工确认可公开、事实有依据并区分 PASS / FAIL / NOT_RUN / NOT_VERIFIED。

审核未完成时不得创建公开分支/PR。保密与授权证明不放进本公开仓库，存放于依法合规的私有环境。AI 检查不能替代有权主体的授权或医疗数据合规审查。

## 第二道门禁：Pages 展示之前

入库后 GitHub 上已公开可读，不等于可在网站推广。另行人工批准网站展示，并要求：
1. 案例元数据 `website_review: approved`；
2. `governance/site-publications.json` 的 `published_case_ids` 中有相同 CASE 编号；
3. PR 审核确认正文可公开展示，授权的真实依据留在私有环境。

机器只检查两份标记相符，**无法证明真实授权**。不满足要求默认拒绝。空白名单表示无经验案例在 Pages 上线。

## 经验与方法文件

文件名仅允许 `experience/cases/CASE-0001.md` 和 `experience/methods/METHOD-0001.md` 这类模式。使用 [模板](CASE_TEMPLATE.md)。源码中的真实项目/人员/组织标识绝不写入。禁止把私有证据粘贴进 PR 描述或错误日志。

## 部署与回滚

网站源码和 Hash 路由不迁移。构建只复制 `index.html`、允许的本地 CSS/JS/SVG 和批准的案例页到 `dist/`。CI 检查完整文件清单与原网站资源逐字节一致；网站源码/发布脚本改动跑 Chrome PC/H5 回归。

撤销 Pages 发布：将案例移出白名单并重新构建部署。**这不能清除公开仓库旧提交、PR、浏览器缓存和第三方副本**；发现泄露应走正式安全事件处置流程，不要擅自改写历史。

## 允许的协作方式

一次合并同类治理需求、一个完整 PR、集中人工验收。Agent 自测要记录命令和实际结果，不能凭缺失证据声称已通过或上线。
